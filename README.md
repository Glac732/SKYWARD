# SKYWARD

**Project status: EXPANDING PLAYABLE PROTOTYPE — NOT A VERIFIED RELEASE BUILD**

SKYWARD is a Unity 6.3 LTS flight-simulation prototype. The current source now includes a runtime front end, three physics presets, four flight-school lessons, six mission types, pilot career statistics, three procedural airport environments, selectable weather, touch controls and procedural aircraft/weather audio. These are prototype implementations using generated geometry and code-driven systems—not commercial-quality aircraft assets or a finished online simulator. It is not certified flight-training software.

## Requirements

- Unity Editor **6000.3.0f1** (Unity 6.3 LTS).
- The Unity Editor components/packages resolved by Package Manager, including URP 17.3.0, uGUI 2.0.0 and Unity Test Framework 1.4.6.
- A desktop system capable of running the Unity Editor. Runtime performance has not been profiled.

## First-time project setup

1. Download or clone the repository.
2. Open the project root in Unity **6000.3.0f1** and allow Package Manager to resolve packages and the Editor to compile.
3. In the Unity menu, choose **SKYWARD → Create / Rebuild Demo Scene**. This creates/configures the URP assets, writes the demo scene and registers it in Build Settings.
4. Open `Assets/Scenes/SKYWARD_Demo.unity`.
5. Press **Play** in the Editor.

The scene is generated by an Editor menu action; a pre-generated `.unity` scene is not currently committed. The first setup step has not yet been verified in a running Unity Editor in this development environment.

## Current controls

| Input | Action |
|---|---|
| W / S | Pitch |
| A / D | Roll |
| Q / E | Rudder |
| Left Shift / Left Ctrl | Increase / decrease throttle |
| Space | Wheel brakes |
| B | Parking brake toggle |
| G | Landing gear toggle |
| F | Cycle flap settings |
| X | Engine toggle |
| C | Cockpit / chase camera |
| Right mouse + move | Camera look |
| Mouse wheel | Chase camera zoom |
| Esc | Pause / resume simulation |

The desktop runtime uses Unity's legacy `Input` API. Android builds receive an on-screen touch-control overlay. Configurable key bindings, the new Input System and gamepad/joystick mappings are not implemented.

## Implemented source systems

- Rigidbody-based aircraft force and moment integration.
- Estimated trainer aerodynamic configuration: dynamic pressure, lift, drag, induced drag, flap/gear drag, stall lift reduction, sideslip force, control moments and rate damping.
- Propeller thrust model with airspeed falloff and local fuel consumption.
- Three WheelColliders, suspension/friction setup, steering and wheel braking.
- Gear, engine, flap and parking-brake state controls.
- Custom-mesh trainer fuselage and swept wing, cockpit dashboard geometry, instrument faces, seat, yoke, control surfaces and three physics/livery presets.
- Three selectable procedural airport layouts: Al Khor desert, Coastal Bay and Highland Regional.
- Procedural cloud clusters, directional sunlight, fog/low-visibility presets, wind profiles and rain particle effects.
- Runtime main menu, aircraft selection, four flight-school lessons, six mission challenges and pilot career/achievement tracking.
- Animated flaps, ailerons, elevators and rudder driven by pilot control inputs.\n- Post-landing flight debrief with telemetry-based landing score and grade.\n- Android touch controls for pitch, roll, rudder, throttle, brakes, gear, flaps and cockpit/chase camera switching, plus procedural engine/wind ambience audio.
- Chase/cockpit camera toggle, mouse look and chase zoom.
- Runtime flight HUD and a seven-field cockpit text instrument strip backed by live controller values.
- Local PlayerPrefs save data with a backup key and basic sanitisation.

The trainer model and airport are deliberately primitive/procedural development assets. They are not production aircraft/environment art. The cockpit is not a detailed 3D flight deck.

## Build, test and download from GitHub Actions

The repository includes `.github/workflows/unity-build-and-test.yml`. It is configured to run Unity EditMode/PlayMode tests, create a Windows x64 player ZIP and create an Android ARM64 APK.

### One-time Unity licence setup

GitHub-hosted runners need an activated Unity licence. In the repository, open **Settings → Secrets and variables → Actions → New repository secret** and add:

- `UNITY_LICENSE`: the full contents of your activated Unity `.ulf` licence file.
- `UNITY_EMAIL` and `UNITY_PASSWORD`: your Unity account credentials if required by the selected activation method.

For Unity Personal, activate it in **Unity Hub → Preferences → Licenses → Add → Get a free Personal license**. On Windows, the licence file is normally at `C:\\ProgramData\\Unity\\Unity_lic.ulf`. Open that file in a text editor, copy its complete contents, and paste them into the GitHub secret named `UNITY_LICENSE`. Add the email/password as separate secrets only if GameCI's activation method requests them.

Never commit a licence file or password into the repository or paste them into this chat. The workflow checks for `UNITY_LICENSE` before starting the Unity jobs. Without it, no Unity tests or player binaries can be produced.

### Run and download

1. Open the repository's **Actions** tab.
2. Select **SKYWARD Unity Build and Test**.
3. Choose **Run workflow** on the `main` branch, or wait for a push to `main` to start it.
4. Open the run and wait for the jobs to finish.
5. Under **Artifacts** at the bottom of the run page, download:
   - `SKYWARD-Windows-x64` — unzip it and launch `SKYWARD.exe`.
   - `SKYWARD-Android-ARM64-APK` — install `SKYWARD.apk` on a compatible Android device.
   - `SKYWARD-Unity-Test-Results` — inspect the EditMode/PlayMode test report and logs.

Only call a build verified when its job completed successfully. A successful player build still needs hands-on gameplay, graphics and device testing before public release.

## Tests and verification

Test source is present for aerodynamic calculations, save behaviour, aircraft/ground-contact integration, full-session startup, airport/weather creation and rendered-frame diagnostics. **22 test cases are authored** across EditMode and PlayMode assemblies; they have not been executed in Unity until the Unity licence secret is configured and the GitHub Actions workflow runs.

The GitHub Actions workflow checks project metadata, expected package and assembly references, presence of required source files, selected setup-code invariants and basic C# delimiter balance. It is a source-validation workflow only. It does **not** compile Unity C#, run EditMode/PlayMode tests, build a player, inspect rendered graphics, or benchmark performance.

## Not currently delivered

There is no compiled Windows executable/installer, Android APK/AAB, iOS/macOS/Linux player, signed release, or verified downloadable application build yet. The current aircraft choices are performance presets on one procedural airframe, not separate detailed aircraft. Airport variants share a runway layout and are not geographically accurate real airports. Training, missions, career and achievements are initial offline systems; navigation instruments, full progression balancing and robust save migration remain incomplete. Weather effects are procedural prototypes, not a full meteorological simulation. There are no production aircraft/environment/audio assets, detailed cockpit model, comprehensive settings/accessibility/localisation suite, multiplayer/network backend, cloud save, content updater or measured device performance profiles.

Do not present this repository as a finished or release-ready game until those systems are implemented as required and the actual Unity build/test/device checks have passed.

## Recommended verification before any public demo

1. Open the project in the exact Unity Editor version above and resolve all Package Manager/compiler errors.
2. Run all EditMode and PlayMode tests; fix any failures rather than treating the current source-validation workflow as a test pass.
3. Rebuild the scene and inspect the Console for errors/warnings.
4. Play a complete ground-roll → take-off → climb/cruise → approach → touchdown → rollout sequence; inspect gear, braking, control directions, stalls and instruments.
5. Inspect the graphics in Game view at more than one aspect ratio; the existing primitive art should be replaced before presenting the project as premium quality.
6. Build and smoke-test each declared target platform on actual hardware before distributing an installer or mobile package.
7. Replace generated aircraft/airport geometry with licensed production assets, then profile GPU/CPU/memory on target Windows and Android devices.
8. Implement and test a real online service (identity, matchmaking/relay, authoritative session state and moderation) before claiming multiplayer.

Flight coefficients are prototype game-simulation estimates, not validated real-aircraft performance data.
